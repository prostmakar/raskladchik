# Раскладчик — исходники

Программа для Windows из трёх частей (выбор при запуске):

**Трубы** — длина реза и врезки для деталей из трубы и проката, раскладка по хлыстам, закупка.
**Лист** — проверка и автоисправление DXF для листового лазера, длина реза и врезки, раскладка деталей на листе.
**Редактирование PDF** — закраска организаций, печатей, фамилий в PDF/TIF/JPG/PNG с сохранением в PDF и переносом в «Трубы».

Трубы:

- **x_t** (Parasolid, текстовый), **IGES** и **STEP** — точный расчёт по 3D-модели, просмотр модели в 3D; профили: прямоугольная/квадратная/круглая труба, уголок, швеллер;
- **PDF** — чтение профиля, длины и отверстий с чертежа, с подтверждением;
- **TIF** (сканы) и ручной ввод — форма рядом с чертежом;
- **Раскладка по хлыстам** со стыковкой скосов и таблицей закупки.

Лист:
- **DXF** — чтение LINE, ARC, CIRCLE, LWPOLYLINE, POLYLINE, SPLINE (NURBS), ELLIPSE, INSERT (блоки, массивы, зеркало), единицы $INSUNITS;
- **проверка**: мусор, двойной рез, «круг в круге», разрывы, наложения на стыках, микрообъекты, осевые линии; исправление — только по кнопке («Исправить» / «Исправить все» / «Вернуть как было»); неисправимое (незамкнутый контур, пересечения) — помечается;
- **материал, толщина, газ** у каждой детали (+ «применить ко всем / к выбранным»), **вес** и **площадь под покрытие** (одна сторона и полностью);
- **запись чистого DXF** (R12, замкнутые полилинии с дугами) в папку «Исправленные DXF» на рабочем столе;
- **раскладка на листе** по группам «материал + толщина»: свободная форма / по габариту, повороты, зеркало, детали в отверстия, общий рез для прямоугольных, несколько листов с повтором одинаковых;
- **Excel (.xlsx)**: детали, раскладка, картинки листов. Трубы — одна книга .xlsx (Детали + Закупка + Раскрой) с обеих кнопок, плюс **деловые отходы / трубы заказчика** в раскладке по хлыстам.
- **Площадь под покрытие** после раскладки: лист — полная (2·S + периметр·t) и одна сторона; трубы — наружная и полная (по граням 3D-модели: `analyzeModel` → `areaOuter/areaFull`; для ручных/PDF — `Calc.coatPerim(профиль) × L`). На экране — главное, в Excel — всё (врезки только в Excel).

Работает без интернета и без установки. Интерфейс — HTML/JS, внешний .exe открывает его в окне Edge/Chrome в режиме приложения.

## Сборка

Нужно: **Python 3.8+** и **Go 1.24+** (https://go.dev/dl/). Node.js — только для тестов.

```
python build.py            # dist/Раскладчик.html и .exe
python build.py --no-exe   # только страница
node tests/test_calc.js    # проверки
```

Собирать можно на Windows, Linux или macOS: exe кросс-компилируется (`GOOS=windows`, без cgo).

Для быстрой разработки интерфейса удобно открывать `dist/Раскладчик.html` прямо в браузере: это та же программа, только без .exe. После правки `src/*` — снова `python build.py --no-exe` и обновить страницу (F5).

Иконку меняют в `tools/make_icon.py` (нужен Pillow), затем `python tools/make_icon.py`.

## Как это устроено

### Запускатель (launcher/main.go)
- Встраивает собранную страницу (`go:embed app.html`).
- Поднимает локальный сервер на `127.0.0.1:47817` (только этот компьютер) и открывает страницу в Edge (или Chrome) с ключом `--app=` — окно без адресной строки. Адрес постоянный, поэтому `localStorage` (списки деталей, настройки) сохраняется между запусками.
- Файлы, переданные в аргументах (перетащили на значок .exe), подставляются в страницу вместо метки `/*STARTUP*/`: x_t — текстом, остальное — в base64. Если программа уже запущена, второй exe передаёт файлы первой (`/api/startup`) и открывает ещё одно окно.
- `/api/save` пишет исправленные DXF (или PDF из редактора — `folder`, `b64`) в `Рабочий стол\<Исправленные DXF | Отредактированные PDF>\<дата время>\`, `/api/open` открывает эту папку в Проводнике. Запросы принимаются только с заголовком `Host: 127.0.0.1:47817` и `Content-Type: application/json` (чужие сайты так отправить не могут).
- Страница отмечается каждые 5 с (`/api/ping`), при закрытии окна шлёт `navigator.sendBeacon('/api/bye')`: если после этого 4 с нет запросов (перезагрузка страницы их даёт) — exe завершается, его можно сразу удалить или заменить. Без «до свидания» — выход через 150 с тишины (свёрнутое окно отмечается не реже раза в минуту).
- Версия сборки (`-X main.version=…`, ставит build.py) отдаётся в `/api/ping`. Если при запуске порт занят программой другой версии — ей отправляется `/api/quit`, и новая версия занимает порт. Той же версии — передаются файлы и открывается ещё одно окно.
- Каждый запуск (новое окно, флаг в `sessionStorage`) начинается с пустых списков: прошлые переносятся в `xtcut.prev` / `sheet.prev`, их можно вернуть кнопкой на стартовом экране. Настройки (хлыст, лист, зазоры, допуски, материал) сохраняются.
- Если порт занят чужой программой — запасной режим: страница из файла в `%LOCALAPPDATA%\DlinaRezaTruby\`, исправленные DXF скачиваются ZIP-архивом.

### Редактирование PDF (src/pdfedit.js)
- Файлы: PDF — как есть; TIF — через `Media.tiffToPdf`; JPG/PNG/BMP — в PDF-картинку (150 dpi). Всё открывается pdf.js (`window.__pdf`).
- Поиск: текст страницы (с поправкой кодировки Компаса: символы U+01C9…U+0208 сдвинуты на 0x247) по шаблонам организаций/кавычек/печатей/адресов; фамилии — точечно: слова с буквами в строке каждой метки «Разраб./Пров./…/Утв.» левее графы «Дата» (рамка на слово, `one:true` — не склеиваются; затем `tighten()` ужимает её до чернил: страница рисуется ~4200 px, строки/столбцы, тёмные > 55% ширины/высоты рамки, — линии таблицы, берётся только клетка между линиями у центра рамки); если таких слов нет (фамилии кривыми) — вся колонка; встроенные картинки — по списку операторов с учётом матрицы (печати). Страница — скан, если картинки занимают > 50% и текста почти нет: тогда ищутся цветные пятна (насыщенность > 55, ячейки 8 px) и графы основной надписи по ГОСТ 2.104 от найденной рамки (правая/нижняя линия рамки, левая — самая правая линия, подходящая под формат A4/A3/A2 по «ширина рамки = лист − 25 мм»; фамилии — клетки 17…40 мм × 5 мм в 6 нижних строках, только где есть чернила; организация — правые 50×15 мм).
- Просмотр: колесо — масштаб к курсору (сразу CSS-размер, перерисовка pdf.js через 180 мс), перетаскивание пустого места / правой кнопкой — прокрутка. «Проверено, следующий файл» — `goNext()`.
- Вывод: каждая страница рисуется до 220 dpi (≤ 3600 px) с белыми прямоугольниками; ч/б — DeviceGray + Flate (`CompressionStream`), цветная — JPEG 0,9; свой минимальный писатель PDF. Текст под закраской физически отсутствует.
- Сохранение: `/api/save` с `{folder:'Отредактированные PDF', files:[{name, b64}]}` → `Рабочий стол\Отредактированные PDF\<дата время>\`; без exe — ZIP. «Перенести в трубы» → `__app.addOne(имя.pdf, …, байты, текст вне закраски)`.

### Окна хлыста и листа
- Трубы: клик по схеме хлыста (`data-pat="группа:схема"`) — окно: детали и количество (в хлысте и × число одинаковых хлыстов), позиции от/до, разворот, общий рез, остаток. «3D (тест)» — модель хлыста: контур сечения по профилю, торцы деталей по форме торцов из раскладки (4 угла — билинейно, у уголка/швеллера — 17 точек вдоль полок).
- Лист: клик по листу (`data-sheet`) — окно с масштабируемой картинкой и списком деталей на листе; наведение подсвечивает все такие детали.

### IGES (src/iges.js)
- Разбор разделов G/D/P (Hollerith-строки считаются в байтах, единицы — по полю 14 раздела G, преобразования 124).
- **Тело (186 → 514 → 510 → 508 → 504/502)**: рёбра — по спискам 504 (геометрия — кривая 126/110/100/102, обрезается по вершинам 502), грани — по 510, две грани у ребра — по вхождению в петли 508.
- **Поверхности (144/142)**: каждая обрезанная поверхность — грань; границы разбиваются на сегменты, общие рёбра находятся по совпадению концов и середины (0,02 мм). Если нет пространственной кривой — берётся кривая в параметрах поверхности.
- Поверхности 120 (вращения, так пишет C3D/Компас) — по оси и образующей: цилиндр/конус/плоскость.
- Шов цилиндра (ребро, дважды входящее в одну грань) резом не считается.
- Плотность точек на NURBS-кривых — до 3000 на кривую (кривые пересечения труб бывают на 300+ участков), для расчёта точки упрощаются до 0,004 мм, длина считается до упрощения.
- Поверхности 128 (NURBS) классифицируются по сетке точек: плоскость (PCA, отклонение < 0,002 мм) или цилиндр (ось — перпендикуляр ко всем нормалям, окружность — МНК). 190/192 — аналитически. Остальное — по точкам границы.
- Кривые: отрезок / дуга окружности (точная длина r·угол) / общая NURBS (плотная выборка + Ричардсон).
- Дальше — то же ядро `XTCut.analyzeModel`, что и для x_t: ось, наружная поверхность, рёбра реза, контуры, профиль, толщина, форма торцов.
- Углы торцов для показа и для общего реза — по плоскости, в которой лежит контур торца (если торец не плоский — «фигурный»).
- Для 3D-просмотра в результате хранится `view` — рёбра (упрощены до 0,05 мм, координаты с шагом 0,1 мм) и номер контура реза у режущих рёбер. Если localStorage переполнен — сохраняется без `view`.

Проверено на 16 деталях МХ014 (Inventor 2024, IGES-тело) и 9 трубах Ø89×4,5 с отверстиями под врезку (C3D Converter / Компас, файлы до 10 МБ): профили 100×50×5 и 50×50×4, скосы 45°, отверстия Ø10,2–Ø30, фигурные торцы.

### STEP (src/step.js)
- Разбор ISO-10303-21: простые и сложные записи `( A(...) B(...) )`, строки, перечисления, ссылки.
- Единицы: `SI_UNIT(.MILLI.,.METRE.)` → мм, без приставки → м, `CONVERSION_BASED_UNIT('INCH')` → дюймы.
- Тело: `ADVANCED_FACE → FACE_(OUTER_)BOUND → EDGE_LOOP → ORIENTED_EDGE → EDGE_CURVE`; у ребра две грани — по вхождению в петли (шов — одна грань дважды). Несколько оболочек — берётся самая большая.
- Кривые: LINE, CIRCLE/ELLIPSE (направление — по `same_sense`), B_SPLINE (с кратностями узлов, рациональные), SURFACE_CURVE/SEAM_CURVE. Поверхности: PLANE, CYLINDRICAL_SURFACE, CONICAL_SURFACE — аналитически, B_SPLINE_SURFACE — по сетке точек (как в IGES).

### Открытые профили: уголок, швеллер (xtcut.js → analyzeModel)
- Периметр выпуклой оболочки сечения размечается по длине; каждая наружная грань занимает дугу периметра. Если остаётся большой непокрытый участок (> 12% периметра и > 2t) — профиль открытый.
- Наружные грани в пределах 1,6·t от краёв разрыва — кромки полок: рёбра с ними не режутся (лазер режет по наружной поверхности полок, кромка — это толщина).
- Торец открытого профиля — контур, покрывающий ≥ 85% пути по наружным граням. Две плоскости полок → уголок, три → швеллер.
- Форма торцов для раскладки у открытого профиля — не 4 угла габарита (у уголка один угол — пустота), а 17 точек вдоль наружных полок от кромки до кромки (`shape.sym = 'path'`). Разворот концами (равнополочный уголок — полки меняются местами, швеллер — полки меняются местами) = обход точек в обратном порядке; зеркального отражения нет. Так детали со ступенькой на полке (одна полка короче) встают «валетом».
- Проверено на 8 уголках 25×25×3 (SolidWorks 2024, STEP AP203) по чертежам: прямой торец 50 мм, фаски 5×45° (54,14 мм), пазы 179,9 мм (165 по кромке, глубина до 10, выемка 26×7), 6 отв. Ø7.

### Чтение x_t (src/xtcut.js)
Текстовый Parasolid нельзя читать подряд без полной схемы, поэтому используется **поиск кандидатов с перекрёстной проверкой**:
1. Строки тела файла склеиваются (перенос каждые 80 символов — не разделитель).
2. В каждой позиции, где может начинаться запись, пробуем разобрать нужные типы по известным раскладкам полей: FACE 14, LOOP 15, EDGE 16, FIN 17, VERTEX 18, POINT 29, LINE 30, CIRCLE 31, ELLIPSE 32, PLANE 50, CYLINDER 51, CONE 52, SPHERE 53, TORUS 54. Метка `255` при первом появлении типа учитывается в обоих вариантах.
3. Ложные кандидаты отсеиваются проверкой связей: FIN ↔ EDGE ↔ LOOP ↔ FACE, VERTEX ↔ POINT, кривая ↔ ребро, поверхность ↔ грань — повторяется до неподвижной точки.

Координаты в x_t — в метрах, в программе — миллиметры.

### Расчёт реза по 3D
1. **Ось трубы** — направление, для которого суммарная площадь «параллельных» граней (плоскости с нормалью ⟂ оси, цилиндры с осью ∥ оси) максимальна.
2. **Наружная поверхность** — такие грани, все точки которых лежат на выпуклой оболочке проекции детали на плоскость ⟂ оси.
3. **Рёбра реза** — рёбра, у которых ровно одна из двух граней наружная.
4. Рёбра группируются в замкнутые контуры по общим вершинам. Контур, охватывающий профиль по кругу, — **торец**, остальные — отверстия/вырезы. Один контур = одна врезка.
5. Толщина стенки — расстояние от наружной плоскости до параллельной внутренней (или разность радиусов).
6. **Форма торцов для раскладки**: осевая координата каждого торца в 4 углах габарита профиля (`shape.lo/ro`).

Сканы TIFF: CCITT G3/G4, LZW, Deflate, PackBits, JPEG (сжатие 7 с общими таблицами JPEGTables, старое сжатие 6), полосы и плитки.

Длины: отрезок — точно, дуга окружности — точно (направление дуги по знакам FIN и кривой), эллипс — численно. B-сплайны и кривые пересечения пока не читаются — длина такого ребра берётся по хорде, и программа предупреждает.


### Лист: проверка DXF (src/dxf.js, src/dxfclean.js)
1. Чтение: секции HEADER/TABLES/BLOCKS/ENTITIES, кодировка UTF-8 или CP1251. Блоки разворачиваются матрицей (масштаб, поворот, массив, зеркальная OCS `230=-1`). Сплайны — вычисление NURBS (де Бур) с адаптивным шагом 0,002 мм, эллипсы — ломаной. Мусор (текст, размеры, XLINE…) считается и выбрасывается, выключенные слои пропускаются.
2. Дубли: отрезки на одной прямой с перекрытием сливаются; дуги/окружности с общим центром и радиусом (±0,02 мм) — объединение углов; «почти совпадающие» (±0,05 мм) с перекрытием по углу — тоже; сплайны — если все точки одного лежат на другом.
3. Граф: концы ближе допуска «стягивать» (0,1 мм) — один узел. Микроотрезки (оба конца в одном узле) удаляются.
4. Цепочки: обход узлов с выбором самого прямого продолжения. Крошечные цепочки (габарит < 0,5 мм) — мусор. Концы открытых цепочек ближе допуска «закрывать» (1 мм) соединяются отрезком.
5. Наложения на стыках: если следующий элемент разворачивается назад (≥ 155°), лишний заход обрезается по точке, где элементы расходятся.
6. Открытые цепочки из штриховых/осевых типов линий удаляются, остальные — ошибка «незамкнутый контур».
7. Контуры: вложенность (чёт — наружный, нечет — отверстие), пересечения рёбер — ошибка. Наружный контур + его отверстия = деталь; несколько наружных — несколько деталей в файле.
8. Запись: R12, каждый контур — замкнутая POLYLINE с выпуклостями; сплайны приближаются дугами и отрезками с точностью 0,01 мм; окружности — CIRCLE.

Проверено на 30 чертежах ПраймАвто (dxf с ошибками / исправлено Андреем): длина реза и число контуров совпадают с ручным исправлением (расхождение до 0,8 мм на деталь там, где Андрей перерисовал сплайн, а программа закрыла разрыв отрезком).

### Лист: раскладка (src/nest2d.js)
- Растровый метод: ячейка ≈ длина листа / 4000 (0,75 мм для 3000). Ячейка занята, если её центр ближе `зазор/2 + полдиагонали` к детали — так любые две непересекающиеся маски гарантируют зазор не меньше заданного.
- Для каждой строки листа хранится длина свободного/занятого участка справа — проверка «влезает ли» и прыжки через занятое идут по интервалам маски, без перебора клеток.
- Порядок: по площади выпуклой оболочки, крупные первыми. Для каждой детали перебираются ориентации (повороты, зеркало; одинаковые маски отбрасываются), берётся место с наименьшим правым краем, затем нижним («вниз-влево» вдоль длины листа). Для повторяющихся деталей поиск продолжается с прошлого места.
- Отверстия: если разрешено, маска детали хранится с отверстиями, и в них ложатся мелкие детали.
- Общий рез: прямоугольные детали одного типа ставятся блоком без зазора (столбцы по ширине листа), общие кромки вычитаются из длины реза.
- Лист заполняется, затем считается, сколько раз его можно повторить при оставшихся количествах.


### Лист: исправление по кнопке, вес, площадь (src/sheetui.js)
- Анализ (`DXFClean.analyze`) всегда строит и исправленную геометрию, и счёт «как есть» (`rawCut` — сумма длин всех режущих объектов вместе с двойными, `rawPierces` — число отдельных цепочек). У детали флаг `fixed`: пока он не поставлен и есть замечания уровня `fix`, в таблице, раскладке и Excel используется «как есть». Кнопка «Исправить» только ставит флаг — исходный файл не нужен, поэтому работает и после перезапуска.
- Уровни замечаний: `fix` (исправляется), `info` (единицы, скрытые слои, несколько деталей в файле — только справка), `warn`, `err` (не исправляется).
- Вес = площадь (наружный контур минус отверстия) × толщина × плотность (7850, AISI — 7900). Площадь «полностью» = 2 × площадь + длина реза × толщина.
- Раскладка: детали группируются по `материал|толщина`, каждая группа раскладывается отдельно (последовательно в Web Worker).

### Трубы: деловые отходы (src/calc.js → nestWithStock)
- Отрезки `[{L, n}]` перебираются от длинных к коротким; для каждого запускается `nestShapes` на остатке деталей и берётся самый заполненный хлыст этой длины. Остальное — на целые хлысты. Неподходящие отрезки возвращаются в `unused`.
- `nestShapes(…, kerf, …, sharedKerf)`: `kerf` — расстояние между деталями (по умолчанию 5 мм), `sharedKerf` — ширина одного общего реза при стыковке скосов (0,3 мм).

### Ручной расчёт (src/calc.js)
- Сечение задаётся как путь по наружной поверхности: профильная труба (скруглённый прямоугольник, R по умолчанию 2t), круглая, уголок (две полки), швеллер.
- **Косой торец**: путь растягивается по стороне, видимой на виде, в 1/sin α (α — угол к оси; «к торцу» = 90° − угол). Это точная длина линии реза по наружной поверхности.
- Отверстия π·d, пазы 2(l−w)+πw, произвольный доп. рез с числом врезок.
- `parseDrawing()` — эвристики для текста PDF: профиль по шаблону `A×B×t ГОСТ …` (тип — по ключевому слову или номеру ГОСТ), длина — наибольшее «чистое» число, отверстия — `N отв.` + ближайший диаметр, углы — числа с `°`.

### Раскладка (src/calc.js → nestShapes)
- Каждая деталь — длина L и положение левого/правого торца в 4 углах габарита профиля. Так описываются любые скосы (трапеция, параллелограмм, скос по разным сторонам).
- **Допустимые повороты** зависят от профиля — только поворот, без зеркального отражения (`OPS`): прямоугольная труба — 4, квадратная и круглая — 8, равнополочный уголок — 2, неравнополочный — 1, швеллер — 2.
- Детали ставятся встык: следующая сдвигается до касания с предыдущей в любом из 4 углов плюс ширина реза. Если торцы совпадают (общий косой рез), зазор = ширина реза / sin α.
- Жадный алгоритм (best-fit и first-fit по убыванию длины, берётся лучший) с просмотром на шаг вперёд — чтобы детали чередовались валетом.
- Масса — площадь сечения × 7850 кг/м³.

### Сканы и PDF (src/media.js)
Сканы в TIFF обычно сжаты CCITT G4. Отдельного декодера нет: TIFF заворачивается в мини-PDF (изображение с фильтром `CCITTFaxDecode`, `LZWDecode` или `FlateDecode`), и его рисует pdf.js. Для G4 pdf.js нужен `jbig2.wasm` — он встроен в страницу (base64) и отдаётся через свою `BinaryDataFactory`, поэтому работает без сети и с `file://`.

## Данные детали (в localStorage, ключ `xtcut.v2`)

```js
{ id, src: 'xt'|'pdf'|'tif'|'man', name, file, qty, mode: 'both'|'one'|'none',
  status: 'fill'|'check'|null,                       // ждёт ввода / проверки / готово
  // ручные детали:
  prof: { type: 'rect'|'round'|'angle'|'channel', a, b, t, r },
  L, ends: [{ ang, ref: 'axis'|'face', side: 'a'|'b' }, {…}], shape: 'trap'|'para',
  holes: [{ n, d }], slots: [{ n, l, w }], extra, extraN,
  // x_t: результат анализа
  res: { length, profile, prof, shape, contours, warnings } }
```

Чертежи (PDF/TIF) хранятся только в памяти, между запусками не сохраняются.

### Версии и обновление
- Версия — в файле `VERSION` (`1.1`, каждое исправление `1.2`, `1.3` …). `build.py` вшивает её в страницу (`__APP_VER__`) и в exe (`-X main.version`).
- Адрес обновлений — `release.json` → `{"repo": "владелец/репозиторий"}` (публичный репозиторий GitHub), вшивается в exe (`-X main.repo`).
- Выпуск версии: поднять `VERSION` (например `1.2`), добавить `notes/v1.2.md` (что нового — это видно в окне обновления) и отправить в `main` репозитория `prostmakar/raskladchik`. GitHub Actions (`.github/workflows/release.yml`) прогоняет тесты, собирает exe и публикует релиз `v1.2` с файлами `Raskladchik.exe` (по нему ищется обновление) и `Raskladchik_v1.2.zip`. Если релиз с этой версией уже есть — ничего не делает.
- `launcher/update.go`: `/api/update/check` — GitHub API `releases/latest`, сравнение версий по числам (1.10 > 1.9); `/api/update/apply` — скачать exe рядом (`.raskladchik-new.exe`, проверка размера и `MZ`), переименовать себя в `*.exe.old` (работающий exe переименовать можно), поставить новый, запустить с `--after-update` (без нового окна). Новая версия видит старую на порту (другая `ver`) и просит её закрыться; страница ждёт `/api/ping` с новой версией и перезагружается. `*.old` удаляется при следующем запуске.
- Порт и `app` в `/api/ping` прежние (`dlina-reza`), поэтому Раскладчик заменяет запущенную «Длину реза и раскладку», а localStorage (списки) остаётся тем же.
